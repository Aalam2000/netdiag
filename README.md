# NetDiag

Мониторинг доступности роутера и интернета с проводного сервера.
Работает бесконечно, пока не остановишь вручную.
Пишет лог, потом одной командой строит человекочитаемый отчёт
с классификацией сбоев: кто виноват — роутер или провайдер.

## Что делает

Каждые 5 секунд проверяет TCP-подключение к 8 целям:

**Локальные (проверка роутера TP-Link 192.168.0.1):**
  - 192.168.0.1:80
  - 192.168.0.1:443

**Внешние (проверка интернета):**
  - DNS  8.8.8.8:53      (Google DNS)
  - DNS  1.1.1.1:53      (Cloudflare DNS)
  - DNS  9.9.9.9:53      (Quad9 DNS)
  - HTTPS google.com:443
  - HTTPS cloudflare.com:443
  - HTTPS github.com:443

Если все внешние цели недоступны подряд дольше 30 секунд —
фиксируется "сбой доступа в интернет" с точным временем.

## Как определяется виновник

В момент каждого сбоя скрипт смотрит, отвечал ли роутер:

  Роутер  |  Интернет  |  Вердикт
  --------|------------|---------------------------------------
  недоступен | недоступен | Проблема роутера TP-Link (192.168.0.1)
  доступен   | недоступен | Проблема на стороне провайдера
  доступен   | доступен   | Норма

В отчёте каждый сбой помечен явно:
  "Причина: проблема роутера TP-Link (192.168.0.1 не отвечал)."
  или
  "Причина: проблема на стороне провайдера
   (роутер был доступен, интернет отсутствовал)."

В итоговой сводке — счётчик: сколько сбоев по вине роутера,
сколько по вине провайдера.

## Структура

    /opt/netdiag/
    ├── netdiag.py            # основной скрипт
    ├── Dockerfile            # образ python:3.12-slim
    ├── docker-compose.yml    # запуск контейнера
    ├── data/                 # создаётся автоматически
    │   ├── netdiag.jsonl     # сырой лог (по строке JSON на замер)
    │   ├── netdiag.log       # лог приложения (старт/стоп/GAP)
    │   ├── heartbeat         # метка последнего замера (детект простоя)
    │   └── report.txt        # сгенерированный отчёт
    └── script/
        └── netdiag.sh        # управление: start/stop/report/...

## Установка (один раз)

    cd /opt/netdiag
    chmod +x script/netdiag.sh
    sudo systemctl enable docker       # автозапуск Docker после ребута
    docker compose up -d --build       # первый запуск

Дополнительно — сделать команду `netdiag` доступной из любого места:

    sudo ln -s /opt/netdiag/script/netdiag.sh /usr/local/bin/netdiag

После этого при включении сервера Docker стартует сам, и контейнер
netdiag поднимается автоматически (restart: unless-stopped).

## Команды

    netdiag start      # запустить мониторинг (пересобирает образ)
    netdiag stop       # остановить мониторинг
    netdiag restart    # перезапустить
    netdiag status     # статус контейнера + последние строки лога
    netdiag log        # живой лог контейнера (Ctrl+C для выхода)
    netdiag raw        # последние 10 сырых замеров из JSONL
    netdiag report     # построить отчёт по накопленным данным
                       # (не останавливая мониторинг)
    netdiag down       # удалить контейнер (данные в data/ остаются)
    netdiag clean      # удалить контейнер И папку data/

Если симлинк не создан — те же команды через `./script/netdiag.sh`.

## Типовой сценарий

1. Запустить:
       netdiag start

2. Убедиться, что пишет (через 30 секунд):
       netdiag raw
   В каждой строке все 8 целей должны быть "ok": true.

3. Оставить на сутки или двое. Ничего делать не надо.
   Периодически можно смотреть:
       netdiag status

4. Через сутки-двое — забрать отчёт:
       netdiag report
   Отчёт печатается в терминал и сохраняется в ./data/report.txt

5. Остановить (когда закончил):
       netdiag stop

## Простой сервера (отключение питания)

UPS нет. Если питание пропадёт:
  - сервер выключится, netdiag перестанет писать;
  - данные за период простоя потеряны физически;
  - когда сервер включится, Docker поднимет контейнер автоматически;
  - скрипт при старте увидит разрыв в heartbeat и запишет
    в лог "GAP detected", а в отчёт попадёт строка
    "Внимание: в период наблюдения сервер был недоступен ...".

Период простоя НЕ считается сбоем сети — он явно выделен
в отчёте отдельным блоком.

## Настройка

Всё в начале netdiag.py:

    LOCAL_TARGETS     — список целей для проверки роутера
    EXTERNAL_TARGETS  — список целей для проверки интернета
    INTERVAL_SEC      — период опроса (по умолчанию 5)
    TCP_TIMEOUT       — таймаут TCP-подключения (по умолчанию 2 сек)
    OUTAGE_MIN_SEC    — минимальная длительность серии неудач,
                        чтобы считать это сбоем (по умолчанию 30 сек)

После правки — перезапустить:

    netdiag restart

## Частые вопросы

Q: Почему TCP, а не ping?
A: В этой сети ICMP заблокирован (роутер 192.168.0.1 не отвечает
   на ping). TCP-подключение работает и даёт тот же RTT.

Q: Как понять, что виноват роутер, а не провайдер?
A: Смотри строку "Причина:" под каждым сбоем в отчёте.
   Если шлюз 192.168.0.1 не отвечал во время сбоя — это роутер.
   Если шлюз отвечал, а интернета не было — это провайдер.

Q: Что делать, если сбоев нет?
A: Значит, канал и роутер исправны, а проблема — у Wi-Fi-клиентов
   за TP-Link'ами. Тогда ставим такого же агента за TP-Link
   (например, малину) и сравниваем два отчёта.

Q: Что делать, если сервер перезагрузился?
A: Ничего. Docker с restart: unless-stopped поднимет контейнер
   автоматически. В логе и отчёте появится строка про простой.
